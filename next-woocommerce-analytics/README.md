# Next WooCommerce Analytics

This is the integration of WooCommerce Analytics into the
[NextAdmin](https://github.a8c.com/Automattic/next-admin) framework for
WordPress. It provides a modern, performant user experience following
NextAdmin's **Materials & Surfaces pattern** with React Query-based data
management, TypeScript support, and modular WP Module architecture for
building WooCommerce reports and dashboards.

## Architecture Overview

The NextAdmin analytics implementation follows NextAdmin's **Materials &
Surfaces pattern** with modular WP Module architecture:

### Materials & Surfaces Implementation

- **Foundation**: NextAdmin framework with `@automattic/admin-toolkit`
- **Surfaces**: Route-based Canvas/Stage/Inspector components  
- **Concepts**: Reusable primitives (data management, widgets, formatters)
- **Screens**: Complete admin routes composed from Materials and Concepts

### Core Layers

- **Data Layer**: React Query with automatic caching, prefetching, and
  comparison support
- **Routing**: TanStack Router with URL parameter management
- **WP Modules**: Reusable components following NextAdmin module system
- **Route Architecture**: Each admin route follows NextAdmin conventions
  with `stage.tsx`, `route.tsx`, and optional `inspector.tsx`

## Data Flow Architecture

### 1. NextAdmin Route Pattern

Routes follow NextAdmin's **Materials & Surfaces** pattern with route
functions in `route.tsx`:

```typescript
// routes/dashboard/route.tsx - NextAdmin route configuration
export const route = {
  // Data preloading using NextAdmin loader pattern
  beforeLoad: async ( { search } ) => {
    const { primary, comparison } = normalizeReportParams( search );
    
    // Prefetch using React Query
    await prefetchReport( 'orders', primary );
    
    if ( comparison ) {
      await prefetchReport( 'orders', comparison );
    }
  },

  // Canvas configuration (NextAdmin surface)
  canvas: async () => {
    return null; // Use Stage surface instead
  }
};
```

### 2. Surface Component Pattern

Surface components (Stage/Inspector) consume pre-fetched data:

```typescript
// routes/dashboard/stage.tsx - NextAdmin Stage surface
export default function DashboardStage() {
  const search = useSearch( { from: '/wc-analytics/dashboard' } );
  const { primary, comparison } = useReport( 'orders', search );
  
  return (
    <Page title="Dashboard">
      <BaseLayout header={<DateFiltersPanel />}>
        <WidgetsGrid />
      </BaseLayout>
    </Page>
  );
}

// packages/widgets - WP Module components
export function OrdersOverTime( { metricKey } ) {
  const { primary, comparison } = useReport( 'orders', search );
  const { data, isLoading } = primary;
  const { data: comparisonData } = comparison;
}
```

### 3. URL Parameter Management

The routing package centralizes URL parameter handling:

```typescript
// packages/routing/src/search/date-range/date-range.ts
writeDateRangeToSearch( {
  navigate,
  to: '/wc-analytics/dashboard',
  range: { from: startDate, to: endDate },
  search: { interval: 'day' }
} );
```

### 4. Data Processing Pipeline

Raw API responses go through automatic processing:

```
API Response → Sanitization → Processing → Caching → Components
     ↓              ↓            ↓          ↓         ↓
String/Mixed → Number Types → Chart Data → React Query → UI Display
```

## Internal Packages

### Core Packages

#### **@next-woo-analytics/data**
React Query-based data management with TypeScript support:
- **Primary + Comparison queries**: Dual data fetching for period
  comparison
- **Automatic prefetching**: Route-based data preloading  
- **Data sanitization**: String-to-number conversion for API responses
- **Caching & invalidation**: Smart cache management with React Query
- **TypeScript integration**: Fully typed data structures and API
  responses

#### **@next-woo-analytics/routing**  
URL parameter management and navigation utilities:
- **Date range encoding**: ISO string conversion with timezone handling
- **Comparison parameters**: Support for `compare_from`, `compare_to`,
  `comp` flags
- **TanStack Router integration**: Type-safe navigation with search
  params
- **URL state persistence**: Maintains filter state across page
  refreshes

#### **@next-woo-analytics/widgets**
Dashboard widget components with data integration:
- **OrdersOverTime**: Line chart widget for various order metrics
- **Shared helpers**: Chart series builders and metric formatters
- **Responsive design**: Adaptive layouts for different screen sizes
- **Loading states**: Skeleton loading and error handling

#### **@next-woo-analytics/formatters**
Text formatting utilities for consistent data display:
- **Number formatting**: Locale-aware number display with decimal control
- **Currency formatting**: Multi-currency support with symbol positioning  
- **Metric formatting**: Smart formatting for analytics values (K/M suffixes)
- **Date formatting**: Human-readable date range labels

### Supporting Packages

#### **@next-woo-analytics/components**
Shared UI components for analytics interfaces:
- **DateFiltersPanel**: Date range picker with comparison support
- **DateRangePopover**: Calendar-based date selection
- **Preset management**: Common date range presets (Last 7 days, etc.)

#### **@next-woo-analytics/boot**
NextAdmin framework integration:
- **Menu configuration**: WordPress admin menu item setup
- **Icon integration**: Custom dashboard icons for menu items
- **Framework initialization**: NextAdmin-specific boot configuration

#### **@next-woo-analytics/layout**  
Layout wrapper components:
- **BaseLayout**: Standard page layout with header/content structure
- **Responsive containers**: Adaptive layouts for different viewport sizes

#### **@next-woo-analytics/icons**
Custom SVG icon components:
- **Dashboard icons**: Analytics-specific iconography
- **Optimized SVGs**: Tree-shaken icon imports for bundle size

## Comparison with Legacy Implementation

| Aspect | NextAdmin Implementation | Legacy Implementation (`js/src`) |
|--------|-------------------------|----------------------------------|
| **Framework** | NextAdmin + TanStack Router | SiteAdmin + @wordpress/data |
| **Data Layer** | React Query with prefetching | @woocommerce/data store |
| **Architecture** | Package-based modular | Monolithic structure |
| **Routing** | File-based routing | Manual route registration |
| **Performance** | Prefetching + caching | On-demand data loading |
